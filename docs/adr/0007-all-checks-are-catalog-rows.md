# Every Check is a catalog row

There is no more house Check. Every id and message lives in `checks.json`; `CheckDiscovery` no longer reflects over hand-written `ICheck` types. What varies is the engine that owns a row's predicate, chosen by the scope the Check needs: per-file syntax and symbol inspection (Syntax, Symbol, Flow, Taint, Metric — 0006), a whole `Compilation`'s diagnostics for a row that needs cross-file resolution such as `unused-using` (`CompilationEngine`, run once per `Compilation` instead of per tree), or a dedicated run-scoped step for a Check that is not a predicate at all, such as `coverage`, which builds and runs tests (`RunEngine`, still opt-in, still not part of a path-in run by default). A shared predicate is a line in its engine's table; a predicate that is its own analysis is a method on that engine; a Check that needs a different execution scope gets an engine at that scope, not a house type. This supersedes 0002 and 0004 for C# file/compilation Checks, and 0006-coverage-runs-tests's framing of coverage as outside the catalog — coverage's identity and opt-in default now come from `checks.json` like any other row, only its execution stays test-running code.
